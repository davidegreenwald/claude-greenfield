# Deleting or renaming an exported symbol — enumerate the blast radius in BOTH directions

**Adapt, do not copy verbatim.** An always-on `.claude/rules/*` rule (no `paths:`). Install it in any
project where an export rename/delete can leave stale pointers a type-checker never sees. Genericize
the file globs and roots to your tree; keep the both-directions framing and the four checks.

Always-on. Governs any plan that deletes/renames an export (function, const, type), changes an
exported signature, or deletes a whole module or test file. The compiler catches a dangling import
only *after* code is written, and never catches an in-file test still asserting deleted behavior, a
stale prose pointer, or a now-dead survivor. Enumerate at PLAN time and **paste every command's
output into the ticket.**

**The domain is the whole harness surface — code, rules, agents, configs, docs — not just source.** A
stale pointer in a rule or a doc table instructs future work against a deleted artifact; that is the
failure a code-only grep leaves behind (this rule's both-directions form came after a one-direction,
code-only grep left nine stale harness pointers and one dead export behind a green gate). One domain
command, run for each deleted/renamed symbol (and, for a signature change, the old call shape), across
every harness root:

```
grep -rn <symbol> <source roots> <test roots> .claude CLAUDE.md <config files> scripts docs
```

Four checks, two directions — every hit lands in the edit-set, or the plan states why not:

1. **Deleted export → surviving consumers.** The command above. A re-export (`export { X } from …`)
   is itself a consumer; deleting `X` without editing it is a typecheck failure.
2. **Deleted TEST FILE → the live code it covered.** Enumerate the live functions the file exercised
   and prove each still has coverage (drive a mutation on the survivor, or diff coverage pre/post). A
   test file is often the SOLE cover of a surviving branch — re-cover it, unless check 4 shows the
   code itself is dead, in which case delete the code.
3. **References INTO the deleted PATHS.** Run the command on the deleted *filenames*, not just their
   symbols. Imports, `file:line` pointers, prose, config globs, and doc tables all rot when a file
   goes.
4. **Dead-export check on the SURVIVORS.** Run the command on each export left behind. One whose only
   hits are its own definition plus its own test is dead surface: delete it, don't re-cover it. This
   makes a "one generation remains" claim DERIVED, not asserted.

**Do not scope this review by line range** — line numbers shift as edits land, and an assertion of
the deleted behavior can sit outside the block you read. Grep the whole file. Ignore git-ignored
build artifacts (regenerated by build); they are not consumers.
